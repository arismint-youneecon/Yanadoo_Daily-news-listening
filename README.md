# 아침 영어 뉴스 클럽

영어회화 동아리 회원이 매일 아침 영어 뉴스 브리핑을 자기 수준(1~5단계)에 맞춰 듣고 공부하는 웹 앱입니다.
Claude 계정 없이 개인 접속 코드로 들어오며, 관리자는 회원별 접속일과 학습 현황을 볼 수 있습니다.

## 구조

| 부분 | 하는 일 | 위치 |
|---|---|---|
| 웹 앱 | 로그인, 단계 고르기, 오늘의 브리핑 3개, 지난 뉴스, 함께(회원 달별·이번 주 현황), 내 기록, 회원 관리 | `index.html`, `app.js`, `config.js` (GitHub Pages) |
| 콘텐츠 | 날짜별 브리핑, 뉴스마다 1~5단계 버전(대본, 해석, 단어, 음성), 명장면 영어 | `data/<날짜>.json`, `data/index.json`, `data/clips.json`, `audio/*.mp3`, `audio/samples/` |
| 회원 기록 | 접속 코드, 고른 단계, 접속일, 재생·완청·단어 조회 기록 | Supabase (`supabase/setup.sql`, `supabase/update-*.sql`) |
| 매일 갱신 | 아침마다 Claude 예약 작업이 뉴스 3개를 5단계로 만들어 이 저장소에 올림 | `scripts/add_briefing.py` |

## 처음 설정

1. Supabase 프로젝트의 SQL Editor에 `supabase/setup.sql` 전체를 붙여넣습니다. 마지막 줄의 `'관리자 이름'`을 본인 이름으로 바꾸고 실행하면 관리자 접속 코드가 나옵니다.
2. `config.js`에 Supabase Project URL과 anon key를 넣습니다. anon key는 공개용 키입니다. service_role key는 절대 넣지 마세요.
3. GitHub 저장소 Settings → Pages에서 Source를 `main` 브랜치의 `/ (root)`로 지정합니다.
4. 사이트에 관리자 코드로 들어가 `관리` 탭에서 회원을 추가하고, 화면에 나온 코드를 회원에게 전달합니다.

`config.js`의 주소를 비워 두면 서버 없이 이 브라우저에만 기록하는 데모 모드로 동작합니다(데모 관리자 코드 `DEMO2026`).

## 명장면 영어 (10초 장면 외우기)

드라마·영화 공식 YouTube 클립에서 10초 안팎의 구간만 골라, 같은 장면을 단계별로 반복합니다. 영상 파일은 내려받거나 자르지 않고, 공식 플레이어에서 시작·끝 초만 정해 재생합니다(`data/clips.json`). 오늘 화면과 지난 뉴스에서 들어갑니다.

| 단계 | 하는 일 | 횟수 |
|---|---|---|
| 1 | 자막 없이 듣기 | 2번 |
| 2 | 영어 자막 보며 듣기 | 2번 |
| 3 | 영어 자막 · 0.75배 천천히 | 2번 |
| 4 | 영어·한국어 자막, 한 줄 끝날 때마다 멈춰서 따라 말하기 | 1번 |
| 5 | 자막 없이 다시 듣기 | 1번 |

- 아래에 대사와 해석, 꼭 챙길 표현, 발음 요령이 있습니다. 대사는 고른 구간(10초 안팎)만 옮깁니다.
- 1단계부터 5단계까지 이어서 끝내면 점수 +1점(뽀로로와 같은 '영상' 기록).
- 구간 고르기: YouTube '가장 많이 다시 본 구간' 그래프에서 가장 높은 곳을 중심으로, 대사가 있는 10초(±3초)를 고릅니다. 대사 시간은 자동 자막의 단어별 시간을 씁니다.
- 올리는 날: 월·수·금. 매주 한 번 관리자와 함께 다음 주 장면 3개를 미리 고릅니다. 프렌즈 시즌 1 1화부터 이야기 순서대로 진행합니다.
- 장면 고르는 기준: 한 사람이 이어서 말하는 1~2문장(10~20단어) 덩어리, 쉬운 단어지만 원어민식 짜임(예: There's nothing to tell! He's just some guy I work with!), 단어만 바꾸면 내 말로 쓸 수 있는 문장.
- 장면 추가: `data/clips.json`의 `clips`에 넣고 `date`(올리는 날, YYYY-MM-DD)를 적습니다. 날짜가 된 장면 중 가장 최근 것이 오늘 화면에 나오고, 지난 장면은 지난 뉴스 화면에 쌓입니다. `start`/`end`는 초, `lines`의 `t`/`e`는 줄 시작·끝 초, `pause: true`인 줄 뒤에서 4단계가 멈춥니다.

## 듣기 화면

속도는 0.8~1.1배이고, 고른 속도는 다음 뉴스에도 그대로 이어집니다. `끝나면`에서 다 들은 뒤 동작을 고릅니다(기기마다 저장).

- 멈춤: 한 번 듣고 멈춥니다(기본).
- 다시 듣기: 같은 뉴스를 계속 반복합니다.
- 다음 뉴스: 같은 날의 다음 뉴스로 넘어가 같은 단계로 이어서 재생합니다. 마지막 뉴스 뒤에는 멈춥니다. 잠금 화면의 다음/이전 버튼으로도 넘길 수 있습니다.

재생기는 하나를 계속 다시 씁니다. 아이폰은 사람이 누르지 않은 재생을 막지만, 한 번 눌러 재생한 재생기는 다음 뉴스로 바꿔도 이어서 재생할 수 있기 때문입니다.

## 함께 (점수 · 주간 목표 · 레벨)

하루 점수 (한국 시간 하루 기준, 하루 최대 10점, 계산은 `update-4-points.sql`)

| 한 일 | 점수 |
|---|---|
| 접속 | 1점 |
| 그날 처음 끝까지 들은 뉴스 | +3점 |
| 두 번째·세 번째로 끝까지 들은 다른 뉴스 | +2점씩 |
| 그 뒤 같은 뉴스 다시 듣기, 네 번째 뉴스, 뽀로로 끝까지 보기(80% 이상), 명장면 5단계 끝내기 | 1번에 +1점 |

- 기본 화면은 이번 주(월~일) 순위입니다. 매주 월요일 모두 0점에서 새로 시작합니다. 달별 순위도 볼 수 있습니다.
- 주간 목표: 이번 주 20점이면 '목표 달성' 배지.
- 동아리 공동 목표: 회원 1명당 15점 × 회원 수. 모두의 이번 주 점수를 합쳐 채웁니다.
- 지난주 이맘때(같은 요일까지)보다 점수가 오르면 '+N점'을 보여 줍니다(내려간 경우는 표시하지 않음).
- 레벨(지금까지 모은 점수, 내려가지 않음): 새싹 0 → 브론즈 30 → 실버 100 → 골드 250 → 다이아 500.
- 다른 회원에게는 이름, 단계, 레벨, 접속일, 점수, 끝까지 들은 횟수, 영상(뽀로로·명장면) 본 횟수만 보입니다. 접속 코드, 단어 조회 기록, 알림 설정은 보이지 않습니다.
- 뽀로로는 YouTube 공식 플레이어 연결(IFrame API)로 본 시간을 세고, 건너뛴 부분은 세지 않습니다. 연결이 안 되면 영상만 보여 주고 점수는 기록하지 않습니다.

## 난이도 1~5단계

| 단계 | 수준 | 대본 | 음성 |
|---|---|---|---|
| 1 | 토익 300점 | 100~140단어, 아주 쉬운 단어와 짧은 문장 | 느리게, 문장마다 쉼 (여성, 미국) |
| 2 | 토익 500점 | 170~210단어, 기초 단어, 뉴스 말은 쉽게 풀이 | 조금 느리게, 문장마다 짧게 쉼 (여성, 미국) |
| 3 | 토익 700점 | 250~300단어, 뉴스 단어는 한 번씩 풀이 | 보통보다 조금 느리게 (여성, 미국) |
| 4 | 토익 850점 | 300~350단어, 토익 Part 4 같은 라디오 뉴스 | 보통 속도 (남성, 미국) |
| 5 | 토익 만점 | 350~420단어, 실제 뉴스 어휘와 긴 문장 | 빠르게 (여성, 영국) |

회원은 처음 들어올 때 단계를 고르고, `내 기록`에서 언제든 바꿀 수 있습니다. 브리핑 화면에서는 그 뉴스만 다른 단계로 바꿔 들을 수 있습니다.

## 업데이트 SQL

이미 `setup.sql`을 실행한 프로젝트는 새 기능이 생길 때 `supabase/update-*.sql`을 번호 순서대로 한 번씩 SQL Editor에서 실행합니다. 여러 번 실행해도 안전합니다.

- `update-1-levels.sql`: 회원별 단계 저장
- `update-2-push.sql`: 매일 앱 알림 (아래 '매일 알림' 참고)
- `update-3-board.sql`: 회원끼리 달별·이번 주 학습 현황 보기 ('함께' 탭)
- `update-4-points.sql`: 점수, 주간 목표, 동아리 공동 목표, 레벨, 뽀로로 시청 기록

새 프로젝트는 `setup.sql` → `update-1-levels.sql` → `update-2-push.sql` → `update-3-board.sql` → `update-4-points.sql` 순서로 실행합니다.

## 매일 알림

회원은 `내 기록`에서 이 기기의 알림을 켜고 알림 시간(기본 오전 6:40, 10분 단위)을 고릅니다. 안드로이드는 크롬과 삼성 인터넷에서, 아이폰은 홈 화면에 추가한 앱(iOS 16.4 이상)에서 받을 수 있습니다.

| 부분 | 하는 일 | 위치 |
|---|---|---|
| 서비스 워커 | 휴대폰에서 알림을 띄우고, 누르면 앱을 엶 | `sw.js` |
| 매분 확인 | 알림 시간이 된 회원이 있을 때만 발송 함수를 부름. 오늘 뉴스가 아직 없으면 최대 60분 기다림 | Supabase pg_cron (`update-2-push.sql`) |
| 발송 함수 | 표준 Web Push로 암호화해 보내고, 없어진 기기는 지움 | Supabase Edge Function `daily-push` (`supabase/functions/daily-push/index.ts`) |
| 발송 키 | VAPID 개인 키와 발송 비밀값 | Supabase `push_config` 테이블에만 저장 (저장소에 없음) |

설정 순서: `update-2-push.sql` 실행 → Edge Functions에서 `daily-push` 함수를 만들고 이 파일 내용을 붙여 배포 → 함수 설정에서 JWT 확인(Enforce JWT verification) 끄기 → 관리자에게 따로 받은 발송 키 SQL 실행.

## 보안과 개인정보

- 무료 GitHub Pages는 공개 저장소에서 운영되므로, 브리핑 파일(MP3, 대본)은 주소를 아는 사람이면 열 수 있습니다. 접속 코드가 지키는 것은 앱 화면과 회원 기록입니다.
- 회원 기록 테이블은 직접 읽거나 쓸 수 없고, 접속 코드를 확인하는 함수로만 다룹니다. 코드는 해시로만 저장됩니다.
- 10분 동안 틀린 코드가 50번을 넘으면 잠시 로그인이 막힙니다.
- 접속일과 학습 기록을 남기므로 회원에게 미리 알리고 동의를 받아 주세요.

## 음성 파일 보관

MP3는 48kbps로, 뉴스 1개의 5단계 음성을 합치면 약 3MB, 하루 약 9MB입니다. 30일이 지난 음성 파일은 자동으로 지워지고, 대본과 해석은 그대로 남습니다.

저장소 기록(git history)에 지운 음성 파일이 계속 쌓이지 않도록, 매월 1일 아침 작업이 기록을 한 번 정리합니다(현재 파일만 남기고 이전 기록을 합침).
